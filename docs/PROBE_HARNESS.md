# Одноразовый запуск проверки NPC в копии мира

Механизм только для локальной разработки. В обычном запуске без
`Zomboid/Lua/PersonalKnox-probe.txt` мод не регистрирует тестовые события
или фоновые опросы. Завершённый/заблокированный запуск тоже не открывает мир.

После установки соответствующего Probe-адаптера и **полного выхода из игры**:

```
python3 tools/arm_probe.py arm SOURCE_SAVE --seconds 180 --quit-when-done
```

`SOURCE_SAVE` — одно имя каталога под `Saves/Sandbox`. Команда не запускает игру.
Она создаёт **новую** `PersonalKnox-test-*` копию существующим проверенным
копировщиком, сохраняет хеши исходного мира и исходный `latestSave.ini` в
JSON-записи запуска. Только в копию записывается актуальный `mods/default.txt`,
чтобы старые AutoEat/InfiniteAmmo и прочие отключённые моды из исходного мира
не исказили проверку. Сам `default.txt` не меняется. Уникальный токен связывает
новую копию, запись и arm-файл; существующие миры не выбираются автоматически.

После следующего входа в главное меню адаптер один раз вызывает штатную
`MainScreen.continueLatestSave('Sandbox', copyName)`. Перед вызовом arm-состояние
переходит в `running`: штатный ResetLua не запускает загрузку повторно.
Модальные окна, конвертация мира, создание персонажа и Java approvals не
подтверждаются автоматически. Если штатный загрузчик ждёт нажатия для входа,
требуется обычное действие пользователя; отсутствие `world_started` не считать
успешной игровой проверкой.

После настоящего OnGameStart проверяются режим, точное имя копии и токен.
Через прежний ограниченный roster выбирается один живой напарник; ему не
выдаются приказы. В Java передаётся реальный MetaNpcCharacter для читающей
проверки публичного конструктора/очереди. Нет создания действия, предметов,
изменения потребностей или телепорта. До 12 попыток найти NPC, не чаще пяти
секунд; после найденного NPC повторных обходов отряда нет. Между проверками
нет файлового ввода-вывода. Обычные модули продолжают работать в копии.

Сообщения `[PersonalKnox][probe-harness]` содержат nonce и имя мира.
`world_started=true`, `javaNpcTransferApi=public_api_present` и `finished=ok`
должны относиться к **одному** запуску. Это подтверждает загрузку копии и
проход реального NPC через Exposer к публичной Java-проверке. Оно не доказывает
выборочный перенос, питание, расход, видимую анимацию, отдых/работы или FPS.
Ошибки других модулей в течение сцены также нужно разбирать отдельно.

`--quit-when-done` использует обычный публичный выход игры только пока активны
та же Sandbox-копия и токен. Без флага игра остаётся открытой. Переход в другой
мир, замена токена или отмена состояния исключают автоматический выход.

После завершения процесса:

```
python3 tools/arm_probe.py cleanup PATH_TO_RUN_RECORD.json
```

Очистка проверяет хеши исходного мира, убирает arm-файл только своего запуска
и возвращает прежний `latestSave.ini`, **если он всё ещё указывает на эту копию**.
Более поздний выбор пользователя не перезаписывается. Копия и запись остаются
для изучения; обычный список модов не менялся. Если исходный мир изменился,
очистка сообщает это и возвращает ненулевой код: неизменность не считается
доказанной. Игровое сохранение копии может обновиться штатным выходом.

`wait_probe.py PID SOURCE_SAVE` может ждать завершения конкретного подтверждённо
живого игрового процесса, затем вызвать ту же подготовку. Он не завершает игру,
не запускает её снова и заново проверяет отсутствие другого процесса перед
копированием. Таймаут оставляет игру и миры в покое; старый PID не считается
доказательством жизни после его исчезновения или смены start-time.

Проверки `check_probe.py` и `check_arm_probe.py` используют двойники событий
и временные userdata. Они проверяют привязку копии, однократность, сброс Lua,
отсутствие приказов/выхода из обычного мира, лимиты опроса, сохранение исходного
мира/профиля/указателя, гонку изменения профиля и отказ при живой игре.
Реальное поведение штатного загрузчика до первого запуска остаётся непроверенным.
