# Исправление паузы разговоров в 0.4.53

В живом запуске с Java core 0.4.48 журнал несколько раз указал
`Chatter.lua:36`, `Object tried to call nil in poll`. На этой строке после
произнесения реплики вызывался `math.random()`. Пауза `nextAt` из-за ошибки
не обновлялась; следующий допустимый опрос снова доходил до разговора.

Отдельный запуск `J2SEPlatform.newEnvironment()` из **установленного игрового
JAR** подтвердил: `math.random` отсутствует. Обновление 0.4.53 использует
штатный `ZombRand(minGap, maxGap + 1)` для выбора паузы в миллисекундах.
Частота опроса, настройки речи и ограничение работы при низком FPS сохранены.

`python3 tools/check_chatter.py` запускает реальную Kahlua через Java 25 игры,
с игровой `stdlib.lua` и настоящим исходником нашего Chatter. Объекты игрока,
NPC, события и `ZombRand` в тесте — двойники: мир не создаётся и глобальный
генератор случайных чисел самой игры не проверяется. Проверены речь, интервалы
обычно/редко/часто, выключение, отсутствие обхода отряда во время паузы,
ограничение производительности и явная диагностика. Старый исходник на том же
тесте падает после произнесения реплики; исправленный проходит.

Это устраняет воспроизведённую причину ошибки. До загрузки исправления и
повторного запуска сцены с напарником не считать проверенной всю функцию
разговоров в мире. Файлы работающей игры для этой правки не менялись.
