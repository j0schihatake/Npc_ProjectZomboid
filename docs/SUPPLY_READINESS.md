# Проверка готовых запасов NPC

Подготовлено в ветке `supply-safety`; проверка в мире ещё не выполнена.

Java `SupplyEligibility` решает, какие предметы подходят для текущего резерва.
Lua считывает реальные свойства предметов и знание NPC через существующий API.

- Еда: уменьшает голод, разрешена к употреблению, не испорчена, не обгорела,
  опасный сырой продукт приготовлен, NPC не распознаёт её как ядовитую.
- Нераскрытая консерва, требующая открытия, не считается готовой едой. Она не
  удаляется; собственный цикл открытия/готовки здесь не добавлен.
- Вода: непустой FluidContainer с чистой водой и без загрязнения. Смеси,
  неизвестное содержимое и старые контейнеры без проверенного fluid-API не
  подтверждают готовый резерв. Другие напитки не объявляются питьевой водой.
- Повязки: прежняя Java-проверка чистоты и пригодности. Грязные/инфицированные
  материалы не закрывают резерв. Поломанное оружие не закрывает наличие оружия.

Для яда используется `IsoGameCharacter.isKnownPoison(item)`, как в штатном
инвентарном интерфейсе B42. Скрытый `getPoisonPower()` не читается. Это проверка
знаний персонажа, а не всеведение о любом отравленном предмете.

После достижения резерва Java `supplyPlan` возвращает `none`, и обход прекращается.
Пороги не дублируются в Lua. Поэтому значения диагностического снимка могут
отражать достаточный минимум, а не общее число всех вещей. Ошибка необязательного
API отдельного продукта/контейнера не должна останавливать проверку остальных.

Команда диагностики NPC получает дополнительные `foodReady`, `waterReady`,
`medicineReady`, `weaponReady`; снимок не меняет предметы и приказы.

## Что это исправляет и чего ещё нет

Исправляется подсчёт запасов **до выбора плана**. При неподходящих запасах NPC
объявляет настоящий план пополнения с прежним подтверждением. Границы здания,
опасности, вместимости и членства отряда остаются прежними.

Штатный Knox-сбор по категориям ещё не превращается в точный отбор предметов;
перенос выбранного экземпляра и экипировка остаются задачей SELECTIVE_LOOT.md.
Резерв по-прежнему выражен числом предметов, не калориями/объёмом всего маршрута.
Глубина инвентаря ограничена четырьмя уровнями, общего бюджета предметов пока нет;
раннее завершение сокращает работу при готовом резерве, но не решает худший случай
огромного инвентаря с недостающими припасами.

## Проверено

- Java-политика через реальный PersonalKnoxAPI: опасный сырой/приготовленный
  продукт, испорченный/обгорелый/несъедобный продукт, известный яд, пустая,
  грязная и неводная жидкость, некорректные числа.
- Lua-адаптер: реальные аргументы плана, вложенная сумка, чистые повязки,
  поломанное оружие, неподдерживаемый предмет, ранняя остановка и объявление
  пополнения при неподходящих запасах. Сохраняются тесты подтверждения и опасности.
- `python3 tools/build.py` и `tools/check_supply_readiness.py` прошли.
- Реальные NPC, маркировка воды и счётчики в игровом журнале пока не проверены.

Новые Java-методы и Lua должны устанавливаться вместе после общей сборки,
без изменения файлов работающей игры и без обхода подтверждения ZombieBuddy.
