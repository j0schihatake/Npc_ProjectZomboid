# Проверка на копии мира

`python3 tools/prepare_probe_world.py 2026-11-05_06-20-39` создаёт отдельное сохранение
`Saves/Sandbox/PersonalKnox-test-…`. Игра должна быть закрыта. Скрипт сверяет SHA-256
всех файлов исходника и копии, проверяет `players.db` через SQLite `quick_check`.
При ошибке незавершённая копия удаляется. Исходник, `latestSave.ini`, настройки
и список модов скрипт не меняет; игру не запускает.

Открывать копию через «Загрузить», проверяя имя `PersonalKnox-test-…`.
Это отдельный мир, но настройки игры и установленные моды общие. После загрузки
сама игра может переключить «Продолжить» на копию: основной мир затем выбирать
через «Загрузить» по исходному имени.

В рабочей 0.4.4 сначала включить «Показывать диагностику PersonalKnox» в
«Настройки → Моды → PersonalKnox — наш отряд». По умолчанию она скрыта.
При входе в мир с включённой диагностикой PersonalKnox однократно пишет `[PersonalKnox][capabilities]`
в `console.txt`: доступны ли Lua-глобальные классы переноса предметов и узлов
поведения. Для этого не создаются действия, не меняются NPC и не сканируется мир.
Наличие класса ещё не подтверждает корректность переноса или работы его методов.

Для состояния конкретного NPC остаётся команда «Диагностика: NPC и
баррикадирование». Она пишет `[PersonalKnox][probe]`; реальный приказ
баррикадирования проверять отдельно на копии. Успех сборки и проверка базы
сохранения не подтверждают работоспособность поведения NPC в игре.
