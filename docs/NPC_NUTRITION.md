# Выбор еды и воды для NPC

Снабжение и собственное питание используют один адаптер `SupplyItems` и
существующую Java-политику `SupplyEligibility`. Lua читает реальные свойства,
Java решает пригодность. Испорченное, обгорелое, опасное сырое, несъедобное,
известный персонажу яд, пустая/загрязнённая/смешанная жидкость не выбираются.
Скрытая сила яда не читается. Ошибка свойств одной вещи не прерывает поиск.
Счётчики неизвестных свойств в диагностике снабжения сохранены.

Питание не запускается при активном бою, известных опасных целях/NPC-врагах,
существующем действии, смерти или неизвестном API опасности. Используется
прежняя обычная очередь `ISEatFoodAction`/`ISDrinkFluidAction`; мгновенного
расхода вещи или изменения голода/жажды нашим кодом нет. Если голоден и хочет
пить, но подходящей еды нет, найденная питьевая вода не игнорируется.

Проверка выполняется раз в 10 реальных секунд: до двух записей отряда и
128 корневых предметов на выбранного NPC. При низком FPS или режиме
производительности — одна запись/32 предмета; жизненные потребности полностью
не отключаются. Сам FPS проверяется после временного ограничения, а не на
каждом кадре. Обход отряда использует прежний адаптер roster и его ограничения.

NPC проверяются по очереди. Каждый имеет отдельный курсор поиска, чтобы еда
после первых 128 предметов могла быть найдена при следующих проверках. Кэш
содержит только строковые ID и индексы, без ссылок на тела/контейнеры/предметы;
при запуске мира он очищается. Это не общий предел времени обработчика и не
измерение FPS. Вложенные сумки питание пока не обходит; снабжение продолжает
проверять их по прежним правилам. Большой инвентарь при подсчёте запасов всё
ещё требует отдельного ограничения худшего случая.

`tools/check_npc_eat.py` проверяет настоящий адаптер с двойниками игровых
объектов: фильтр, угрозу/занятость, вызов штатных действий, поиск в 100000
предметов, ротацию, уменьшенные бюджеты и сброс. Прежний адаптер падает на
проверке выбора безопасной еды. Java-политика и проверки снабжения пройдены
отдельно. Это не проверка работы анимаций/расхода внутри Knox.

До игровой проверки не считать функцию завершённой: нужна спокойная сцена,
появление врага, новый приказ, отмена действия, еда/вода в сумке, соответствие
инвентаря и потребностей после действия. Пороги 0.60 старого адаптера пока
остаются в Lua; подключение общего Java-плана потребностей — отдельная задача.
