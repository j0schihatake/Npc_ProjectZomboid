# Запуск для агента DeepSeek

Использовать новый `tools/launch_dev.sh`. Код NPC и текущие скрипты DeepSeek
не менялись. Старый `launch_test.sh` временно заменяет основной default.txt;
новый запуск использует отдельный игровой cachedir и обходится без такой замены.
При подготовке создаётся штатный `mods/reset-mods-42_00.txt`: без него первый
запуск B42 очищает даже заранее записанный список модов. Маркеры будущих версий
не создаются, подтверждение Java-модов не затрагивается.

Быстрый dev-запуск с минимальным набором, в фоне без таймаута:

```bash
/home/j0schi/Zomboid/PersonalKnox-dev/tools/launch_dev.sh --detach
```

Для исправленной версии в ветке `review-java-runtime` и рабочей копии DeepSeek:

```bash
/home/j0schi/Zomboid/PersonalKnox-runtime-fixes/tools/restart_dev.sh
```

Доверие двум проектам уже настроено для этого dev-профиля. На новом профиле
добавить к первой команде `--trust-local-builds`.

Первый `--trust-local-builds` сохраняет доверие двум независимым проектам:
PersonalKnox и PersonalWorldGen, каждому по точному ID и каноническому пути.
Далее этот флаг можно не указывать: перед каждым запуском launcher сам вычисляет
новые хеши их объявленных JAR и записывает разрешения в стандартный кэш ZombieBuddy.
Записи чужих модов сохраняются; перед изменением создаётся резервная копия.
Политика находится в dev-каталоге `.local-mod-trust.json`, резервные копии —
в `approval-backups`. Новая папка рабочего дерева требует явного повторного
`--trust-local-builds`. Это не отключает проверки подписей или запреты ZombieBuddy.

`--restart` посылает SIGTERM только PID из своего dev-launch.json после проверки
живого процесса, cachedir и start-time; ждёт выхода и не применяет SIGKILL.
Это перезапуск одноразового dev-сеанса, **не обещание автосохранения игрового мира**:
нужные dev-сохранения следует сохранять через игру до перезапуска. Основные миры
изолированы. `--build` запускает build.py выбранных наших модов после остановки,
затем разрешаются новые хеши и запускается новый процесс. Без `--restart` старая
игра, как и раньше, не завершается автоматически.

Состояние процесса и реальный этап загрузки:

```bash
tools/launch_dev.sh --status
```

Режимы `--profile worldgen` и `--profile both` предназначены для отдельного
генератора и совместного запуска. `--worldgen-source PATH` задаёт его рабочее
дерево. Сейчас PersonalWorldGen ещё не содержит игрового 42/mod.info/JAR:
launcher сообщает об этом, а не подменяет генератор NPC-модом.

Профиль: ZombieBuddy, Viewpoint, Knox, русский перевод Knox, PersonalKnox.
Зависимости добавляются перед требующими их модами. PersonalKnox загружается
**прямо из рабочего дерева агента**, включая уже собранный JAR. Скрипт не
собирает Java автоматически: после изменения Java сначала выполнить
`python3 tools/build.py`, затем перезапустить игру обычным способом.

Полный текущий набор модов и порядок карт для проверки совместимости:

```bash
tools/launch_dev.sh --profile full --detach
```

Другие варианты:

```bash
tools/launch_dev.sh --prepare-only        # Подготовить файлы, не запускать игру
tools/launch_dev.sh --dry-run             # Только показать план; никаких записей
tools/launch_dev.sh --nosteam --detach    # Установленные моды доступны через локальные ссылки
tools/launch_dev.sh --add-mod aparosa_ViewpointI18n --detach
tools/launch_dev.sh --source /path/to/another/PersonalKnox-worktree --detach
```

По умолчанию отдельный каталог — `/home/j0schi/Zomboid-dev/PersonalKnox`.
`--cache-dir /path/to/dev-cache` меняет его. Нормальные сохранения, список модов
и настройки под `/home/j0schi/Zomboid` не перезаписываются. Графика/язык из
options.ini и ModOptions.ini копируются только при первом создании dev-профиля;
дальнейшие dev-настройки сохраняются. Миры и файлы автоматического probe-запуска
не копируются: создать отдельный тестовый мир через меню.

`-debug` включает штатный режим разработки PZ. В текущем OwnNpcDebug агента
F10 создаёт одного собственного NPC рядом с игроком; результат пишется как
`[PersonalKnox][own-debug]` в журнал. Отладочная клавиша — поведение мода,
не функция самого launcher.

Журналы и PID:

- `~/Zomboid-dev/PersonalKnox/console.txt` — игровой журнал.
- `~/Zomboid-dev/PersonalKnox/launch-logs/…log` — stdout/stderr запуска.
- `~/Zomboid-dev/PersonalKnox/dev-launch.json` — PID, команда и пути журналов.

`--detach` возвращает PID сразу; запуск не завершается по таймауту. PID из JSON
не доказывает, что процесс всё ещё жив: проверять его через `ps -p PID`.
Без `--detach` скрипт ждёт игру и возвращает её код завершения. Уже запущенную
игру без `--restart` он не завершает и вторую не запускает. Подготовка профиля
также запрещена, если этот cachedir используется игрой. Для двух доверенных
локальных проектов разрешения новых хешей регистрируются автоматически.
Остальные Java-моды остаются на обычном подтверждении ZombieBuddy.

Workshop-моды связываются в отдельный mods-каталог локальными ссылками, поэтому
не скачиваются повторно. Ссылки указывают на установленные файлы, а не на их
зафиксированный снимок: для воспроизводимого сравнения агенту нужно сохранять
проверяемый коммит и не редактировать Lua/JAR во время прогона.

Проверены `check_dev_launch.py`, `check_dev_trust.py` и реальный цикл:
SIGTERM своего dev-PID → Java-сборка с тестами → разрешение нового хеша
PersonalKnox → запуск в фоне. Получены реальные `loadMods(5 mods)`, Java core
0.8.7 и Lua addon 0.8.7 без ожидания подтверждения. Мир и анимации этим запуском
не проверялись.
