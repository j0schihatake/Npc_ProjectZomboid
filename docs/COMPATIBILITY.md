# Проверка текущей сборки

Дата: 2026-11-05. Игра: 42.21.0, Viewpoint: 0.1.6.1. Проверка манифеста и прошлого журнала не доказывает совместимость всех функций в игре.

## Подтверждённая проблема и исправление

- `ViewpointExtendedSupport` отключён в общем списке и последнем сохранении: в журнале есть Byte Buddy `Cannot assign class java.lang.Object to class viewpoint.interact.LootTargets$Target` непосредственно при его патче `LootTargets.aimed`.
- `ProjectViewpointQOLLegacy0.1.6` оставлен. Его отдельное предупреждение `ThirdPerson.active` по просьбе пользователя отложено.
- Исправлены наши подписи процентов в переводе Ammo Weight: больше нет сырого `%`, который вызывал предупреждение форматирования.
- Наши русские подписи контекстного меню вынесены из Lua в JSON через `getText`; 2026-11-05 пользователь подтвердил в игре: «текст стал норм».

## Изменения интерфейса

- Установлен `DGVViewpointEyes`. Полосы здоровья зомби, цифры урона, контур и комбо отключены в его пользовательском конфиге.
- Дополнительные карта/компас/пинги/ежедневные сводки Eyes отключены, чтобы не добавлять ненужную работу. Стандартная миникарта сохранена.
- Это новый мод для текущей сборки: необходима проверка в игре; другой полноценный HUD параллельно не подключён.

## Карты

- Raven Creek B42, Maplewood, Iris Eyot и Dinglespurt используют `lots=Muldraugh, KY`: это дополнения к основному миру.
- Заголовки клеток проверены: 116 / 4 / 6 / 4 клетки соответственно; пересечений между ними нет.
- Новые Iris Eyot и Dinglespurt включены в общий набор для нового мира. В уже созданное сохранение новые карты не добавлялись, чанки не удалялись.
- В прошлом журнале есть ошибки идентификаторов комнат `BuildingRoomsEditor`. Их конкретный источник и последствия ещё требуют отдельного теста карт.

## Автоматизация персонажа и NPC

- Auto Eat, Auto Drink и Auto Medic не считаются проверенной автоматизацией Knox NPC только потому, что работают на игроке.
- Auto-Eat 0.2.7 проверен по исходникам: подписан на `OnPlayerUpdate`, берёт настройки персонажа и вызывает `player:Eat(food, fraction, false)` напрямую; обычная `ISEatFoodAction` и её анимация не используются. Встроенной интеграции с Knox нет. Для игрока оставлен; анимированное питание NPC этим не считается реализованным.
- Auto Reload — тренировка перезарядки, а не замена Infinite Ammo With Reload. С бесконечным запасом его упражнения требуют отдельной проверки.
- Снабжение PersonalKnox теперь считает только чистые пригодные повязки; резерв — минимум две. Самостоятельное изготовление тряпок пока не реализовано.

## Проверка запуска 0.2.0

- PersonalKnox 0.2.0, его Java API и Lua-адаптер загрузились в игре.
- Viewpoint Eyes подключён; конфиг отключения полос здоровья зомби и цифр урона записан до запуска.
- Ошибка Byte Buddy `Cannot assign class java.lang.Object to class viewpoint.interact.LootTargets$Target` в новом журнале не обнаружена после отключения Viewpoint Extended Support.
- Читаемость ПКМ-меню подтверждена пользователем после загрузки мира. Реальные речь NPC и поведение в мире ещё требуют проверки; загрузка до меню этого не доказывает.

## Включённые моды

0.3.1 подключена в активный каталог после выхода из игры; изменены только Lua/переводы/манифест, JAR остался от 0.3.0. В новом запуске Lua-адаптер зарегистрирован. Проверка колеса/F и новых команд в мире пока ожидается.

В отдельной ветке `barricade` подготовлен 0.4.0: собственные Java-правила материалов/завершения, Lua-адаптер к `SafehouseSubTree`/`BarricadeSubTree`, без модификации или копирования Knox Java. Проверены ограничение запаса, повторный учёт окон, отсутствие ложного завершения при незагруженной цели, отмена зовом/новым приказом, таймер по игровым часам, локальное обнаружение опасности и бюджет 8 заданий/4 за опрос. Реальный запуск нативной работы из этого адаптера пока не проверен; методы постановки goals взяты из доступных Lua-команд Knox, но достаточность для баррикадирования требует проверки в игре. Произвольный дом ещё не поддержан. Прототип не подключён.

Активная 0.3.0 подключена после завершения предыдущей сессии. В новом журнале подтверждены Java core 0.3.0, экспорт API и загрузка Lua. Изменённый JAR прошёл штатное разрешение ZombieBuddy; файл разрешений не редактировался. Команды 0.3.1 подключены после следующего закрытия игры; их поведение в мире ещё не проверено.

Перед запуском обнаружено повторное включение Viewpoint Extended Support в глобальном наборе и новом сохранении `2026-11-05_06-20-39`. Он снова отключён только в этих двух списках, резервные копии в `mod-setup-backup-20261105/compatibility-0643`. Добавленный пользователем Visible Door Damage сохранён; его функции ещё не проверены на всей сборке.

Источник проблемы ПКМ в FPS ещё не изолирован в живой сцене. Проверено по установленному `NpcContextMenu.lua`: координаты NPC/здания вычисляются из позиции мыши и изометрического масштаба. Новый вход «Knox — взаимодействие» использует объект NPC, переданный сборщиком Viewpoint, и штатный построитель действий Knox. Контракт проверен с установленными Lua-файлами сборщика/диспетчера Viewpoint и меню/обработчика выбора Knox, включая повторную проверку доступа к инвентарю после выхода из отряда. Это не доказательство исправления всех случаев ПКМ и не замена проверки FPS в игре.

Пользователь подтвердил появление пунктов при наведении в 0.3.0. При выборе открывалось обычное ПКМ-окно, внутри которого колесо/F Viewpoint не работали. В рабочей 0.3.1 переход в это окно убран: конечные команды добавляются прямо в список Viewpoint. Проверены прямой вызов через установленный `ViewpointInteract.run`, отсутствие создания командного popup, сохранение nil-аргументов и повторная проверка прав/видимости. Реальная навигация колесом/F ещё ожидает проверки после обновления.

Установленный `NpcAreaSelector:pickSquare` использует `screenToIsoX/Y`, а не отдельный выбор поверхности камерой Viewpoint. Точная разметка в FPS не подтверждена; временный способ — разметка в изометрии. Наличие правил хранения/Organizing подтверждено в Lua-интерфейсе, но полный перенос урожая в холодильник ещё не проверен в мире.

Проверены Java-правила расписания и Lua-контракты: GUARD, сохранение исходных часов при повторном применении, отмена, откат частичного сбоя, запрет при неизвестном расписании/без членства/без убежища. UI-проверки подтверждают адресата команды, повторную проверку видимости и членства при выборе, сохранение штатных пунктов, единственное подключение обработчика и соответствие действий/подписей Viewpoint. Реальный интерфейс и анимации ещё не проверены.
